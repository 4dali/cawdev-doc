## Sign in

There is **no signup**. An administrator created your account and gave you a
password. If nobody has, that is the first thing to sort out — see
[Accounts and roles](/admin/accounts-and-roles/).

Passwords are shown exactly once, when they are set, and cannot be read back.
If yours is lost, an administrator issues a new one.

## What you are looking at

Across the top of the console:

| | |
|---|---|
| **Project switcher** | "All projects" is the list; picking one takes you to it. |
| **Roadmap · Runs · Changelog · Settings** | The current project's pages, as tabs. They appear once you are inside a project. |
| **Search… `⌘K`** | The [command palette](/reference/shortcuts/). Type a few letters of any project, page, or roadmap entry and press enter. |
| **Inbox** | Questions from agent sessions waiting on **you**, across every project. A red number means something is stalled until you answer. |
| **Tokens** | Your [agent tokens](/agents/tokens/) — mint, list, revoke. |
| **Users** | Administrators only. |
| **The dot** | Green: the console reached the API. Red: it did not, and that is not something you can fix from the console. |
| **◐** | Theme: dark, light, or follow the system. The console is dark-first and remembers your choice. |

## Open a project

Click a project, or press `⌘K` and type its name. You land on its
[roadmap board](/console/roadmap/); the tabs take you to its
[runs](/console/runs/), its [changelog](/console/changelog/), and its settings
— the git URL, the default branch, and the member list.

:::caution[No projects at all?]
Then you are not a member of any. cawdev answers **404 rather than 403** for a
project you cannot see, deliberately — a URL should not let you discover which
projects exist. Ask an owner to add you.
:::

## Read the board

Six columns, left to right as work moves, with `DECLINED` last because it is an
exit rather than a stage. The important idea is that **a status is not a step in
a workflow** — any status may move to any other. What the rules are about is
what a status *carries*: `CODING` a branch, `SHIPPED` a version, `DECLINED` a
reason.

See [Roadmap statuses](/reference/statuses/) for the full table.

## Then what

<Steps>

1. **Write an entry.** [The roadmap](/console/roadmap/) covers what makes one
   workable by an agent rather than merely readable.

2. **Give an agent the roadmap.** Mint a token, drop the
   [MCP server](/agents/mcp/) into a repository, and your agent can read and
   move entries itself.

3. **Run a session from the console.** Set up the
   [runner daemon](/agents/runner/) once, then press **Start development** on
   an entry and watch it work.

</Steps>
