This is the loop cawdev exists for: point an agent at a roadmap entry and stay
in the conversation while it works — without opening a terminal.

It needs a [runner daemon](/agents/runner/) running somewhere. Set that up
first; it is a one-time job per machine.

## Start it

<Steps>

1. Open an entry that is `PLANNED`, `IN PROGRESS` or `CODING`.

2. Press **Start development…**. The branch is pre-filled following the
   project's convention (`r12-slug-of-title`) — change it if you know better.

3. The form shows **which runners are live**, and warns when none is. Press
   **Start**.

</Steps>

:::note[Why you do not pick a runner]
Runners **claim** work off a queue rather than being assigned it. What matters
is whether anything is listening, not which machine you chose — so the console
shows you that, and lets the queue decide. If nothing is live, the run simply
waits until a runner starts.
:::

A project runs **one live run at a time**, because runs share a working copy.
Starting a second is refused, readably.

## Watch it

The run detail updates itself every few seconds while the run is alive, then
stops — a finished run cannot change, and leaving the tab open should cost
nothing.

<Steps>

1. A runner claims it; the state goes **Running**.

2. The agent moves the entry to `CODING` naming the branch. **It does this
   itself** — the console does not. That way `CODING` means "someone is working
   on this" rather than "someone queued this".

3. Progress messages arrive as it goes.

4. If a decision is genuinely yours, it **asks and stops**.

</Steps>

## Answer it

An unanswered question turns the **Inbox** badge red anywhere in the console. It
appears the moment the question is asked, not on a timer — the badge waits on
the same primitive the agent is blocked on.

Answer from the run detail or from the Inbox: click one of the offered options,
or write your own words. The session resumes immediately, and the thread keeps
**who answered and when**.

:::tip[Nothing sweeps a run that is waiting on you]
A session stalled on a person is correct behaviour, and a person may reasonably
take a day. What *is* swept is a run whose **runner** goes quiet for five
minutes — that one is failed with a reason saying so.
:::

## Stop it

**Cancel this run** appears on a live run, behind a confirm. It reaches the
daemon on its next poll and takes down the agent's whole process tree — an
agent that started a build should not leave it running.

Anything already committed stays committed. Re-running means a **new run**,
which keeps the history of what actually happened.

## The runs page

Every run the project has had, newest first: state, entry, branch, runner and
duration, with a badge showing how many runners are live. A queued run with
nothing to take it is the failure mode worth seeing first, so it is shown in
red.
